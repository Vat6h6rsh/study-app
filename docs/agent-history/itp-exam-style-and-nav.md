## The 21 Nov exam pattern (shared openly in the course; use it)
Computer-based, 5 questions, each a complete short C program (about 20-45 lines) with 10 blanks. Each question has a descriptive title naming 2-3 combined concepts (pattern: "<Concept A>, <Concept B> and <Concept C>"), a DETAILED statement of what the program must do (rules/formulas/conditions), and the EXPECTED OUTPUT printed under the program. Programs use hard-coded data (no scanf/stdin), so output is deterministic. The five concept mixes on the paper were:
  P1. array of daily values + loop accumulation (total) + counting with a threshold condition + a derived "remaining/unused" count + float result printed with %.1f
  P2. user-defined functions taking an array: linear search returning the first index or -1, counting with % (e.g. even numbers) + a global variable shadowed by a local variable of the same name (printing both)
  P3. string reverse using strlen and an index formula, terminating with '\0', plus counting characters with ctype (isupper etc.) and counting a specific character
  P4. struct with a char array field + strcpy + pointer to struct with -> + a function that modifies the struct through a pointer (swap two fields) + arithmetic on fields (area/perimeter-like)
  P5. file write with fprintf then fclose, reopen in "r" and read with fscanf into a malloc'd int array (NULL check), find a minimum/maximum, free
Write close VARIANTS of these patterns with different data, names, scenarios and twists (e.g. max instead of min, odd instead of even, lowercase/digits instead of uppercase, static vs global scope, scale instead of rotate, average instead of minimum, append mode, calloc) - but never reproduce the exact original programs, titles or data.
