## Problem (user)
"The program window needs to be scrolled and explored, like empty-space traversal, to read the program. Not ideal."
The program is shown inside a box with its own scrolling (vertical and/or horizontal), so the student has to pan around inside it and across empty space to read the code.

## Fix, at ALL screen sizes (practice, mock, reports)
1. No inner scroll container for the program: the code block renders at its full natural height in the page flow (remove max-height / fixed height / overflow:auto on the code pane and its wrappers). The page scrolls, not the code box. Keep the answers side panel (desktop side-panel mode) sticky beside it so it stays visible while the page scrolls; if the program is shorter than the panel, fine.
2. No horizontal panning: soft-wrap long lines at every width with a hanging indent that preserves each line's original indentation visually (wrapped continuation lines indent past the original indentation), so formatting still reads as C. Line numbers stay aligned with the first visual row of each line (subtle on phones or hidden as already decided). Blank chips/inline inputs may wrap to the next visual row as a unit, never split.
3. No wasted empty space: size the code font and line-height for comfortable reading (about 14-15px on phones, 15-16px desktop, line-height ~1.5); the program column takes the available width; trim excessive padding; avoid large blank areas to the right of short programs on desktop (e.g. cap the code column at a readable measure and let the answers panel or margins take the rest, per the guide's line-length guidance for code).
4. Keep: Explain-code comments (they also wrap with the same hanging indent), chips/inline inputs, reveal fill, live validation, keyboard toolbar on phones, desktop Side panel | Inline toggle, all themes and contrast, accessibility.
5. Checks: extend the browser/UI checks to assert, for EVERY ITP blanks question at 390px, 768px and 1280px: the code element has no internal scroll (scrollHeight <= clientHeight + 1 and scrollWidth <= clientWidth + 1) and the page has no horizontal overflow.
