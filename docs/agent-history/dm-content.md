## 3. Questions: src/data/dm/*.json (+ types.ts)
Design question types that maximise AUTO-GRADING for a typing-based maths exam, while keeping full step-by-step model solutions. Suggested types (refine as needed, document all):
- "truth-table": variables + list of column expressions (sub-expressions up to the full statements); student fills T/F for every row/column; key computed; optional follow-up mcq (equivalent? tautology?).
- "formula": a final closed-form answer in n (e.g. a_n = 2*3^n + n*2^n) checked by numeric evaluation at several n (store test points + expected values; the UI will need a tiny safe expression evaluator: + - * / ^ parentheses, n, integers); also used for counting answers like 2^(n^2).
- "numeric": a single number (MST total weight, number of edges/vertices, pigeonhole minimum, counts) with tolerance 0.
- "set-answer": a set of elements typed comma-separated, order-insensitive (maximal/minimal elements, LUB/GLB, equivalence class, Hasse cover edges as pairs).
- "properties": tick boxes (reflexive / irreflexive / symmetric / antisymmetric / transitive / equivalence relation / partial order / lattice / bipartite / Eulerian / Hamiltonian / planar ...), each auto-graded.
- "partition": equivalence classes of a relation entered as groups; order-insensitive.
- "mst": weighted graph (vertices, edges with weights, optional layout coordinates) + algorithm (kruskal | prim with a start vertex); student enters the edge sequence step by step; checker accepts any valid order under tie-breaks; plus total weight; model answer in the professor's exact step format.
- "steps": proof/derivation questions answered in free text, with a model solution broken into numbered steps and a marking rubric per step (marks), plus optional auto-checked "checkpoints" (e.g. characteristic roots, final formula, basis value) using the types above.
- "mcq" for concepts/traps.
Every question: id, subject 'dm', topic (ids above), title, source ("Past paper N Qm" or "Original"), priority ('core' | 'past' | 'extra'), difficulty, marks, prompt (typed-exam wording, maths in the plain-text notation from section 1), the type-specific fields, a full STEP-BY-STEP model solution typed exactly as the student should type it in the exam, and a short concept note.
